# Project wiki maintenance

Read [wiki/index.md](wiki/index.md) for project context and [wiki/AGENTS.md](wiki/AGENTS.md) for the wiki schema and maintenance workflow. Verify behavior against source code before implementation; summaries and old phase reports can be stale.

When an authorized project change affects architecture, APIs, ingestion, retrieval, security, configuration, operations, decisions or validation, update the relevant wiki pages as part of the same task. Keep source citations and review dates current, update the index for added/renamed pages, and append a concise entry to wiki/log.md. Record new evidence and unresolved contradictions rather than implying an old test run validates new code. A documentation-only or unrelated change does not require rewriting every page.

Do not read private environment files, copy secrets or customer policy contents into the wiki. Existing docs/ files remain the source collection; do not move or rewrite them merely to maintain the wiki.
